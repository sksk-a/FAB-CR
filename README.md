### 2. Refresh-токены (Практика 9)
- Разделение access- и refresh-токенов
- Генерация refresh-токенов
Генерация refresh-токена выглядит точно так же, как и генерация access-токена, но с
другими параметрами:
`
jwt.sign(
{
sub: user.id,
username: user.username,
},
REFRESH_SECRET,
{
expiresIn: REFRESH_EXPIRES_IN,
}
);
`
Где REFRESH_SECRET - отдельный секрет для токенов обновления, а
REFRESH_EXPIRES_IN - время истечения токена, например "7d".

### 3. Хранение токенов на фронтенде (Практика 10)

- Хранение токенов в cookies
- Автоматизация работы с токенами


### 4. Управление доступом на основе ролей
- RBAC (role-based access control)
- Реализация системы ролей на сервере
Для реализации RBAC на сервере создал два middleware: authMiddleware - для
проверки аутентификации пользователя и rolesMiddleware - для ограничения доступа к
эндпоинтам для конкретных ролей. Таким образом, /api/protected-route доступен всем ролям, кроме пользователя, а
/api/protected-admin-route - только администратору. Протестируем.
